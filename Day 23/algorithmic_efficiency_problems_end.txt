1. The following calculates the highest possible product of a list of numbers.

DECLARE highestProduct = -1
FOR i = 0 TO length(listOfNumbers) - 1     
    FOR j = 0 TO length(listOfNumbers) - 1
        product = listOfNumbers[i] * listOfNumbers[j]
        IF product > highestProduct THEN
            highestProduct = product
        ENDIF
    ENDFOR
ENDFOR

Reason for inefficiency:

It is inefficient because it uses nested loops to check every possible pair of numbers, including duplicates an numbers that have already been multiplied against each other (9 x 5 and 5 x 9). It has O(n²) time complexity. It also performs the multiplication operation every time in the loop.

Optimized Version:

DECLARE maxNumber = listOfNumbers[0]

FOR i = 1 TO length(listOfNumbers) - 1
    IF listOfNumbers[i] > maxNumber THEN
        maxNumber = listOfNumbers[i]
    ENDIF
ENDFOR

DECLARE highestProduct = maxNumber * maxNumber

Justification:
This solution is better. The highest product will always be the highest number in the list multiplied by itself. The algorithm will linearly go through the list until we find the highest number, and then perform the "highestProduct" calculation after the loop. This has O(n) time complexity.

2. The following code will check if a given list is sorted:

DECLARE isSorted = true     // boolean flag defaults to true

FOR i = 0 TO length(listOfNumbers) - 1
    FOR j = 0 TO length(listOfNumbers) - 1
        IF i < j AND listOfNumbers[i] > listOfNumbers[j] THEN
            isSorted = false
            BREAK   // exit inner for loop
        ENDIF
    ENDFOR
    IF isSorted == false THEN
        BREAK       // exit outer for loop
    ENDIF
ENDFOR

Reason for inefficiency:

This algorithm is inefficient because it compares every element with the one that comes after it, as a result it has O(n²) time complexity.

Optimized Version:

DECLARE isSorted = true

FOR i = 0 TO length(array) - 2
    IF array[i] > array[i + 1] THEN
        isSorted = false
        BREAK
    ENDIF
ENDFOR

Justification:
The second version is better because it is just checking if each element is less or equal to the number that follows it. Only one pass through the array is required and therefore the complexity is O(n).

3. Finding common elements between two arrays

DECLARE list1 = [1, 2, 3, 4, 5]
DECLARE list2 = [3, 4, 5, 6, 7, 8]
DECLARE common = []

FOR i = 0 TO length(list1) - 1
    FOR j = 0 TO length(list2) - 1
        IF list1[i] == list2[j] THEN
            IF list1[i] NOT IN common THEN
                ADD list1[i] TO common
            ENDIF
        ENDIF
    ENDFOR
ENDFOR

Reason for inefficiency:

This solution checks every element in the first array against (count of n) every element in the second array (count of m). This results in O(n*m) operations.

Optimized Version:

DECLARE list1 = [1, 2, 3, 4, 5]
DECLARE list2 = [3, 4, 5, 6, 7, 8]
DECLARE elementDictionary = {} // dictionary
DECLARE common = []

// Add all elements from list1 to dictionary
FOR i = 0 TO length(list1) - 1
    ADD list1[i] TO elementDictionary
ENDFOR

// Check which elements from list2 exist in the dictionary
FOR i = 0 TO length(list2) - 1
    IF list2[i] IN elementDictionary THEN
        ADD list2[i] TO common
        REMOVE list2[i] FROM elementDictionary // Prevent duplicates
    ENDIF
ENDFOR

Justification:
The optimized version uses a dictionary to store the elements from the first list. In then checks the membership of each element in the second list and will add them to the common list. This results in a complexity of O(n+m), since we only need to loop through each array once.

4. A list of numbers is sorted in a way where the highest number is somewhere near the middle and the numbers on either end are the smalles values in the list. Imaging a triangle to visualize it. This algorithm will find the index of the highest number:

DECLARE list = [1, 3, 8, 12, 4, 2]
DECLARE peakIndex = -1

// Checking every element against all others
FOR i = 0 TO length(list) - 1
    DECLARE isPeak = true
    FOR j = 0 TO length(list) - 1
        IF j != i THEN
            IF (j == i - 1 OR j == i + 1) AND list[j] >= list[i] THEN
                isPeak = false
                BREAK
            ENDIF
        ENDIF
    ENDFOR
    IF isPeak THEN
        peakIndex = i
        BREAK
    ENDIF
ENDFOR

Reason for inefficiency:

This version is inefficient because it checks each element against all of its neighbors in a nested loop fashion, giving O(n²) time complexity.

Optimized version:

DECLARE array = [1, 3, 8, 12, 4, 2]
DECLARE left = 0
DECLARE right = length(array) - 1

WHILE left < right
    DECLARE mid = (left + right) / 2
    
    IF array[mid] < array[mid + 1] THEN
        // Peak is in the right half
        left = mid + 1
    ELSE
        // Peak is in the left half (including mid)
        right = mid
    ENDIF
ENDWHILE

DECLARE peakIndex = left

Justification:
This optimization version uses divide and conquer to find the peak. If the middle element is smaller than its right neighbor, the peak must be in the right half. If it is more than its right neighbor, then the peak is in the left half. This removes half of the search space and acheives O(log n) complexity.
